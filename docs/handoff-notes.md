# 今日存根项目接续记录

日期：2026-05-09

## 1. 已确定方向

产品名暂定为「今日存根」。

核心定位不是「生活小票生成器」，而是「情绪结算 + 生活存根 + 轻量日记 + 分享图生成」。

最重要的一句话：

> 不是记录今天花了多少钱，而是给今天留一张生活凭证。

## 2. 从原始想法到当前方向的变化

最开始讨论的是「生活小票生成器」，包括睡眠、饮品、花费、小确幸等字段。

后来判断它容易变成「记账工具换皮」，并且已有 DaySlip 这类相近产品，因此产品方向调整为：

- 弱化消费、金额、明细、总计
- 强化情绪余额、能量值、保留下什么、没有白过的证据
- 把小票作为视觉隐喻，而不是产品内核
- 从「receipt」转向「stub / 存根 / 凭证」

## 3. 第一版产品边界

第一版应该做：

- 今日生成页
- 票根预览页
- 保存图片
- 本地存档墙
- 单张存根详情
- 3 个以内票根主题
- 本地模板文案

第一版不应该做：

- 记账
- 金额统计
- 消费分类
- 心理咨询
- 公开社区
- 会员付费
- 手机号登录
- AI 强依赖

## 4. 小程序分享限制

后续设计时要注意：小程序通常不能替用户一键发布到朋友圈。

推荐做法：

- 提供「保存图片」作为核心分享路径
- 图片保存到相册后，引导用户自行发朋友圈、微信状态或私聊
- 可以提供「分享给好友」的小程序卡片能力
- 不要把“一键发朋友圈”作为 MVP 承诺

## 5. 历史记录展示决策

历史记录不做统计报表，而做「存档墙」。

设计原则：

- 历史页像一个按日期摆放的生活票根盒子
- 顶部可以有月份切换和轻量月历
- 有记录的日期用小点标记
- 下方用单列票根卡片展示历史记录
- 一天多条记录用叠放票根表示，例如「今日存根 x 3」

避免：

- 情绪折线图
- 能量趋势图
- 月度评分
- 排行榜
- 「你这个月低能量 13 天」这类管理感提示

## 6. 本地数据未来迁移到云端

第一版不上云，但本地数据结构必须为未来云同步预留字段。

关键字段：

- `id`：全局唯一，不要只用日期
- `version`：数据结构版本
- `createdAt`：创建时间
- `updatedAt`：更新时间
- `syncStatus`：同步状态，第一版默认为 `local_only`

后续云版本上线时，推荐流程：

1. 用户登录或开启云同步
2. 小程序检测本地 `syncStatus = local_only` 的记录
3. 弹窗提示「发现本机有 N 条历史存根，是否同步到云端？」
4. 用户确认后批量上传
5. 云端按 `id` 去重
6. 成功后本地记录标记为 `synced`

注意：

- 不能静默上传本地历史
- 必须先取得用户明确确认
- 隐私协议需要说明云端保存的数据类型和删除方式

## 10. V1 情绪价值增强决策

V1 需要加入一层轻量情绪价值设计，但不能把产品做成心理咨询、情绪测试或强鸡汤工具。

已确定加入：

- 随机治愈短语
- 今日小印章
- 今日小物件
- 模块化生活痕迹
- 保存成功后的温柔反馈

推荐展示节点：

- 打开今日生成页时，显示一句顶部轻提示，例如「今天不用解释太多」。
- 选择今日状态后，显示一句与状态相关的短语，例如「能到这里，已经不容易」。
- 生成票根时，把一句「今日判定」固定进票根。
- 保存成功时，弹层显示一句确认感反馈，例如「好了，今天被收好了」。
- 存档空态用低压力引导，例如「第一张存根，会从今天开始」。

实现注意：

- 第一版继续使用本地短语库，不接 AI。
- 用户点击「换一句」才切换短语，不自动频繁变化。
- 生成后保存 `phraseId`、`verdictId`、`stampId`、`objectId`，历史回看保持一致。
- 印章和小物件是纪念物元素，不是成就系统或打卡勋章。

## 11. V1 模块化生活票根决策

最新 V1 方向把早期「生活小票」里的睡眠、饮品、花费、小确幸重新收回来，但不是回到记账产品，而是作为可选的「生活痕迹模块」。

已确定模块：

- 睡眠
- 饮品
- 小花费
- 小确幸

设计边界：

- 用户自己的那句话仍然是票根核心，不被模板短语替代。
- 生活痕迹模块由用户主动添加或关闭，不作为必填字段。
- 小花费只表达「给今天加了什么」，不显示合计、预算、分类统计或消费趋势。
- 票根可以使用小票分行结构，但不要出现支付、找零、收银台、账单管理等语义。
- V1 原型和产品文档已经按这一版更新，后续开发以此为准。
